# 参考网站分析与映射

## 核心原则

参考网站不是模糊灵感。必须先拆解，再映射，再生成。

先判断用户要参考的是：

- 设计系统：色彩、字体、形态、留白和动效。
- 页面骨架：章节顺序、首屏构图、导航和区块连接。
- 具体组件：卡片、画廊、播放器、数据模块等。
- 完整复刻关系：用户明确要求逐区块对应。

除非用户明确要求完整复刻，默认优先保留核心设计语法，并用真实作品内容承接。不得为了对应原站而虚构业务模块。

## 必须拆解

### 结构

- 单页或多页
- 章节顺序和首屏高度
- 导航位置、状态与滚动行为
- 区块连接和页脚
- 桌面、平板、手机的结构变化

### 排版

- 最大宽度和页面边距
- 栅格列数和对齐关系
- 标题、正文与媒体宽度
- 卡片排列和媒体比例
- 区块上下留白与内容密度
- 重叠、错位、悬浮和全宽关系

### 文字

- 字体类型、字号比例、字重、行高和字距
- 中英文组合和标题换行
- 标签、按钮、注释和装饰文字

### 色彩与表面

- 背景、卡片、文字、边框和强调色
- 色彩面积比例、渐变方向和明暗层级
- 圆角、阴影、描边和透明效果

### 组件与交互

- 导航、按钮、标签、项目卡、图片和视频容器
- 数据、序号、分隔线、弹窗和页脚
- 悬停、滚动出现、图片缩放、页面转场和视频播放
- 动画时长、延迟、缓动和减少动态模式

## 映射矩阵

生成前建立：

```text
参考区块
参考结构
视觉特征
交互方式
作品集对应内容
使用的用户素材
必须保留的细节
需要替换的内容
省略原因
```

常见映射：

- 产品或服务卡片 → 项目卡片或专业能力
- 功能模块 → 工作方法或能力证明
- 客户列表 → 技能、服务领域或合作方向
- 产品详情 → 项目详情
- 价格卡片 → 仅在有真实服务信息时映射为服务范围
- 推荐语 → 仅在有真实来源时使用
- Showcase → 作品画廊
- Steps → 工作流程或经历路径

没有真实内容承接的价格、评价、客户 Logo、奖项和 FAQ 应省略。

## 设计系统锁定

在写代码前固定：

```text
主色 / 辅助色 / 背景 / 表面 / 文字 / 边框
中文字体 / 英文字体
H1 / H2 / H3 / 正文 / 注释
容器宽度 / 页面边距 / 栅格 / 断点
圆角 / 阴影 / 图片比例 / 模块间距
按钮 / 标签 / 序号 / 导航
进入动效 / 悬停动效 / 动效速度
```

首页、经历和项目页面必须共享同一套规则。修改一个同级组件时，同步检查全站同类组件。

## 多参考网站

如果用户提供多个参考网站，必须确认：

- 哪一个是主参考。
- 其他网站分别参考哪些部分。

未经用户指定，不混合多套视觉语言。

## 无法访问

如果链接无法访问、需要登录或无法判断主要视觉，请用户提供页面截图、屏幕录制、备用链接或重点参考页面。

没有足够证据时，不自行设计后声称已经严格参考。

## 保留与替换

优先保留：排版关系、网格、留白节奏、色彩关系、组件形态、交互逻辑、动效节奏和整体调性。

必须替换：品牌名称、原站文案、图片、Logo、商标和与用户无关的业务内容。

## 是否需要原创重排

比较参考站和用户素材的媒体数量、主比例、主体安全区及信息密度。

只有直接映射会造成主体严重裁切、媒体变形、大面积空白、视觉拥挤或文字无法容纳时，才调用 [original-layout-and-copy-quality.md](original-layout-and-copy-quality.md)。调用原因必须具体记录。
